# ZeBot — merged build

Это объединённая версия ZeBot:

- сохранён существующий паспорт и `templates/passport.html` без изменения дизайна;
- добавлены экономика, банк, работы, магазин, рынок, профили/XP, партии, выборы, тупперы и расширенная админка;
- система организаций переведена на единую PostgreSQL-схему и исправлена несовместимость старой таблицы организаций;
- добавлена HTML/Playwright-карточка организации;
- добавлены красивые HTML-приветствия новых игроков с аватаром игрока и иконкой сервера;
- в `/setup` появились переключатель приветствий и выбор канала приветствий.

## Запуск

1. Установить Python 3.11+.
2. Установить зависимости:
   `pip install -r requirements.txt`
3. Установить Chromium для Playwright:
   `playwright install chromium`
4. Создать `.env` по образцу `.env.example`:
   - `DISCORD_TOKEN=...`
   - `DATABASE_URL=postgresql://...`
5. Запустить:
   `python main.py`

## Приветствия

Откройте `/setup` с правами staff:

- `Приветствия: ВКЛ/ВЫКЛ` — включает/выключает автоматическое приветствие;
- `Канал приветствий` — выбирает канал;
- после этого новый участник получает сгенерированную HTML-картинку с аватаром, названием сервера и количеством участников.

По умолчанию приветствия выключены, чтобы после обновления бот не начал неожиданно писать в канал.

## Важно для Discord

Для приветствий необходимо включить **Server Members Intent** в Discord Developer Portal. Боту также нужны права `View Channel` и `Send Messages` в выбранном канале.

## Миграция БД

Схема создаётся автоматически через `asyncpg`. Если на PostgreSQL уже была старая версия ZeBot, код добавляет недостающие поля и переносит старые организации в новую структуру настолько, насколько это возможно автоматически.

Паспортные данные и шаблон паспорта не удаляются.

## Внешнее хранение данных

Папка `assets/flags` больше не используется и не является хранилищем данных. Бот не сохраняет пользовательские флаги, логотипы и фотографии на диске рядом с кодом.

- PostgreSQL задаётся через `DATABASE_URL` и находится отдельно от приложения.
- Медиа загружаются на отдельный сайт/объектное хранилище через `MEDIA_STORAGE_URL`.
- `MEDIA_STORAGE_TOKEN` используется для авторизации загрузки.
- API хранилища должно принимать `POST /api/files` с multipart-полем `file` и возвращать JSON вида `{ "url": "https://files.example.com/files/..." }`.
- В БД сохраняется URL, а не локальный путь/имя файла.

Это позволяет полностью удалить папку с ботом и развернуть его заново без потери данных.
